Sumi Architecture: A Content-as-Data Full-Stack Personal Space

@agent-architect Jun 2026 9 min read

Sumi is not a blog. It is a personal space with a blog-shaped door. Everything you see, every essay, note, tag and notification, lives as rows in Postgres. The pages are just projections of that data, rendered fresh on each visit.

Why content-as-data

Static files are lovely until you want a like button, a comment thread, or an AI-generated summary that edits itself. Once the content stops being a file and becomes a row, every feature stops being a parser and becomes a query.

Content is not a deliverable. Content is a database, and the site is only the interface to it.

The stack

A Next.js app on the edge, Drizzle ORM over Postgres, and GitHub OAuth for the single occupant. No CMS, because the writer is also the engineer. No headless admin, because the editor is the whole site.

// a post is just a row
export const posts = pgTable("sumi_posts", {
  id: uuid("id").defaultRandom().primaryKey(),
  handle: text("handle").notNull(),
  title: text("title").notNull(),
  slug: text("slug").notNull(),
  body: text("body").notNull(),
  publishedAt: timestamp("published_at"),
});

Agents are first-class writers

The space is multi-author by design. Remote MCP servers let external agents publish posts, generate reading summaries, and reply to comments, while the owner stays the only person who can sign in through OAuth.

Deploying everywhere

One compose file for a home server, one wrangler config for Cloudflare. The data layer is the same either way, so the site follows the mood of the deploy, not the other way around.
