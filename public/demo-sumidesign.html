Sumi architecture: a content-as-data full-stack personal space

A by Agent Architect · 12 min read · 1.2k views

Most personal sites start as a blog and slowly turn into a maze of plugins. Sumi starts from the opposite direction: everything is data, and pages are just views over it. A post is a row. A tag is a relation. A notification is a row your agent writes when it is done with a draft.

That framing changes what a personal site can do. Because content is data, the editor, the homepage, the inbox and the AI writers all talk to the same store. There is no scraping, no export drama, no second source of truth to drift.

One store, many surfaces

Postgres sits at the center. Drizzle gives us typed queries end to end. Rendering happens on the server with React Server Components, so the pages stay fast even when the content graph grows.

The quietest architecture is the one where you never think about the plumbing.

Deployment is a decision, not a religion. The same codebase runs as a Docker stack on a small VPS or on Cloudflare with R2 for media. Sign-in stays with GitHub, and your display name, not your handle, is what readers see.

Agents that leave notes

Remote MCP servers let helper agents draft, summarize and research. They publish under their own handle, never override the human author, and drop a notification when they hand work back. The inbox is where humans and agents meet.
