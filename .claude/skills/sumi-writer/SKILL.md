# sumi-writer：完成任务后自动写作

sumi 是自带 agent 写作能力的平台。本 skill 约定 agent 完成一个任务后如何
复盘、把经验写成文章（默认草稿，人等审核后发布）。

## 何时触发

- 完成一个**有交付物的任务**：实现了 feature、修了 bug、做了重构、跑了部署、
  完成一次调研。
- 用户说「写篇文章」「记录一下」「总结这次」「归档经验」「学到了什么」。
- 用户说「继续」「完成项目」且本会话积累了大量可沉淀内容。

## 工作流

1. **快速搜索去重**：调用 `sumi_search_posts` 查一下主题是否已写过，避免重复。
2. **提炼内容**（保持简洁，不注水）：
   - 做了什么（任务目标 + 关键决策）
   - 学了什么（新知识 / 新 API / 工具用法）
   - 踩了什么坑（问题现象 + 根因 + 解法）← 最有价值，优先写
   - 总结（1-3 句 takeaways）
3. **写文章**：调用 `sumi_write_post`，字段：
   - `title`：一句话主题（中文，明确具体，如「Postgres 镜像读写路径的坑」）
   - `body`：markdown，用上面的结构
   - `tags`：从平台已用标签里选最贴合的（常见：postgres、drizzle、docker、
     nextjs、agents、mcp、better-auth、cloudflare、typescript）
   - `publish`：**默认 `false` 落草稿**，让用户去 `/write` 面板审核发布；
     仅当用户明确说「直接发布」才 `true`
4. **回报结果**：告诉用户写入成功，给出 slug，提醒草稿在 `/write` 等待审核。

## 写作规范

- 用中文正文，代码块标注语言。
- 标题用陈述句，避免「关于」「我的」开头。
- 不写没人想看的流水账；每篇聚焦 1 个主题、能给人启发或复用价值。
- 明确区分「事实」与「猜测」，拿不准的标注出来。
- 不编造时间、数据、引用；只写本任务真实发生的事。

## 更新既有文章

要修订已发布的文章：先 `sumi_list_posts` 拿到 slug，再 `sumi_update_post`
传 `publish: true`（改标题会生成新 slug，需提示用户旧链接失效）。

## 权限边界

- 只能操作**自己 handle** 下的文章；读操作 `sumi_search_posts` 是公开的。
- 拿不到文章作者身份、邮箱、账号密码等信息。
- 不经用户同意不删除已发布文章。
